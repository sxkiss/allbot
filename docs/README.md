# AllBot 技术文档

> AllBot 是一个基于微信协议（869 / WechatAPIServer）驱动的智能微信机器人，采用「核心引擎 + 可插拔插件系统 + 可视化管理后台」的分层架构，支持消息处理、定时任务、LLM 对话、朋友圈、文件管理等能力。
>
> 文档生成时间：**2026-08-29**

> ✅ 本索引引用 `01`~`04` 四个模块文档均已生成并可用：`01-core-engine.md`、`02-plugin-system.md`、`03-admin-panel.md`、`04-data-config.md`。

## 1. 整体架构概览

AllBot 自底向上分为四层。最底层是**微信协议层**，负责与微信客户端/协议服务（869 服务、WechatAPIServer）通信，收发原始消息与事件；其上是**核心引擎**，承载 bot 生命周期、消息路由、配置加载、数据层访问等中枢能力；再往上是**插件系统**，以可插拔方式扩展机器人的具体业务能力（目前覆盖 **23 个插件**）；最上层是**管理后台**，基于 FastAPI 提供可视化页面与 OpenAPI 接口（**112 个 API**），用于运维、配置与监控。

各层之间以明确的依赖方向单向调用（协议层 → 核心引擎 → 插件系统 → 管理后台），管理后台主要「只读消费」核心引擎与数据层暴露的状态与接口，不直接耦合微信协议细节。

```
┌─────────────────────────────────────────────┐
│              管理后台 (Admin)                 │
│   FastAPI + Jinja2 · 112 API · 可视化运维      │
└───────────────────────┬─────────────────────┘
                        │ 读取状态 / 调用接口
                        ▼
┌─────────────────────────────────────────────┐
│              插件系统 (Plugins)                │
│        可插拔业务扩展 · 23 个插件              │
└───────────────────────┬─────────────────────┘
                        │ 注册 / 接收消息事件
                        ▼
┌─────────────────────────────────────────────┐
│              核心引擎 (Core Engine)            │
│   bot 生命周期 · 消息路由 · 配置 · 数据层访问   │
└───────────────────────┬─────────────────────┘
                        │ 协议收发
                        ▼
┌─────────────────────────────────────────────┐
│            微信协议层 (Wechat Protocol)         │
│        869 服务 · WechatAPIServer              │
└─────────────────────────────────────────────┘
```

## 3. 快速上手

- **启动方式**
  - 直接运行：执行仓库主程序（如 `python main.py` / `python run.py`，以仓库根 README / `用户手册.md` 为准）。
  - 容器运行：参考 `docs/docker本地构建.md` 进行本地 Docker 构建与启动。
- **访问后台地址**
  - 默认 `http://<服务器IP>:8080`（由 `main_config.toml` 的 `[Admin].host`/`port` 控制，默认值 `0.0.0.0:8080`）。
  - 首次访问会跳转 `/login`，使用 `[Admin].username`/`password` 登录（注意默认凭据 `admin/admin123` 会被启动拦截，须先修改）。
- **主要配置入口**
  - 根目录 `main_config.toml`：包含 9 个配置段——`[Protocol]`、`[Framework]`、`[WechatAPIServer]`、`[Admin]`、`[Logging]`、`[Performance]`、`[AllBot]`、`[AutoRestart]`、`[Notification]`，详见 `04-data-config.md` §3。
  - 环境变量（优先级最高）：`ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_HOST` / `ADMIN_PORT` / `ADMIN_SECRET_KEY` 等。

## 5. 已知重要事项摘要

从各模块文档提炼的关键安全 / 已知限制点（详细见对应子文档）：

- **CSRF 防护缺失**：管理后台所有状态变更 API 均无 CSRF Token / Origin 校验（仅依赖 `SameSite=lax`），公网部署风险较高。（`03` §6.4、§7.2）
- **配置写回双轨并存**：`/settings`（tomlkit 结构化写回）与 `/notification`（手写 TOML 整体覆盖 `[Notification]`）两套实现，格式处理与注释保留行为不一致，长期应统一到 `config_service`。（`03` §7.1）
- **Web 聊天内存存储**：`web_chat_api.py` 固定会话 ID `webchat`，历史消息存于内存（`web_sessions`），重启即清空。（`03` §7.7；`webchat功能说明.md`）
- **两套消息计数并存**：`database/message_counter.py`（SQLite）与 `database/MessageCounter.py`（JSON 旧实现）并存，计数口径可能不一致。（`04` §1.2）
- **OpenAPI 未鉴权**：`/docs`、`/redoc`、`/openapi.json` 默认公开暴露全部接口定义（含内部路径与参数）。（`03` §7.5）
- **默认凭据被启动拦截**：示例 `admin/admin123` 无法启动，须先修改 `main_config.toml` 的 `[Admin].username/password`。（`03` §7.3）
- **默认端口公网暴露**：未配置时监听 `0.0.0.0:8080`，公网部署需自行加防火墙 / 反代 / HTTPS。（`03` §7.4）
- **DOW 插件双轨**：旧框架 `plugin_routes.py` 与新框架 `plugins.py` 并存，新增功能应使用新命名空间。（`03` §7.9）
- **WebSocket 部分端点未显式鉴权**：`/ws`、`/ws/update-progress` 未做登录校验（风险较低，仍建议收敛）。（`03` §6.5）
- **配置热更新范围有限**：仅 `Notification` 触发条件可服务热更新，协议/框架/端口等核心改动需重启 bot 生效。（`03` §7.10）
