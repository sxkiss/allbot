# AllBot 系统架构文档

## 1. 系统概述

AllBot 是一个基于微信的智能机器人系统，通过整合多种 API 和功能，提供了丰富的交互体验。系统通过 `adapter/` 下的各平台适配器接入多种平台，具备插件扩展能力，集成了 AI 对话功能，并提供了完整的管理后台。

### 1.1 系统主要功能

- **微信消息处理**：接收和发送各类微信消息（文本、图片、语音、视频等）
- **Web对话功能**：通过管理后台界面直接与机器人对话
- **多平台适配器**：支持 QQ、Telegram、Web、ocwx、WeChat Observatory、企业微信智能机器人（wecom_bot）等多平台接入
- **AI 对话能力**：集成多种 AI 模型，支持智能对话
- **插件系统**：可通过插件扩展系统功能
- **管理后台**：提供 Web 界面管理系统
- **数据存储**：使用 SQLite 数据库存储配置和消息
- **多平台接入**：协议实现由 `adapter/` 下的各平台适配器提供

## 3. 核心组件

### 3.1 主流程控制 (main.py)

main.py 是系统的入口点，负责初始化和协调各个组件：

- 读取配置文件
- 启动管理后台
- 初始化数据库连接
- 启动机器人核心
- 配置文件变更监控
- 自动重启功能

### 3.2 机器人核心 (bot_core/ 包)

`bot_core/` 是系统的核心包，由以下模块组成：

- `orchestrator.py`：启动编排入口
- `message_listener.py`：入站队列消费与消息监听
- `client_initializer.py`：客户端初始化
- `service_initializer.py`：服务装配
- `status_manager.py`：状态监控与通知
- `ws_message_normalizer.py`：WS 消息归一辅助
- `__init__.py`：包入口

核心职责：

- 消息队列管理（统一适配器模式：只消费 Redis `allbot` 队列，不建协议连接）
- 适配器会话灌入 / 服务装配
- 消息处理和路由（框架统一归一后按 MsgType 分发 / `EventManager.emit`）
- 插件系统管理
- 状态监控和通知

### 3.3 微信 API 接口 (WechatAPI/)

WechatAPI 目录是**协议无关门面层**（`facade.py` / `errors.py` / `Client/`），对外提供统一的
发送与查询能力，不包含任何具体协议实现。**协议实现位于 `adapter/`**（如 `wechat_869`、`wechat_875`），
各适配器自行持有协议客户端并管理 WS/HTTP 连接。

主框架已协议剥离：**不建立任何微信协议连接**。各适配器各自持有协议客户端（如 869/875），自行管理 WS/HTTP；入站统一写 Redis `allbot` 队列，主框架只消费队列。`enable-wechat-login` 已废弃。

### 3.4 适配器系统 (adapter/)

适配器系统负责接入多平台消息，并将消息写入 Redis 主队列：

- 配置位置：`adapter/<name>/config.toml`（多数适配器默认 `enabled=false`，需显式填写凭据后启用）
- 入口加载：`adapter/loader.py`
- 回复分发：`utils/reply_router.py` + `ReplyDispatcher`
- 当前渠道：QQ、Telegram、Web、Win、wx-filehelper、ocwx、WeChat Observatory、企业微信智能机器人 `wecom_bot`（aibot 长连接；默认关闭）

### 3.5 插件系统

插件系统是 AllBot 的核心扩展机制，包括：

- 插件管理器 (utils/plugin_manager.py)
- 插件基类 (utils/plugin_base.py)
- 各类功能插件 (plugins/ 目录)

插件系统通过装饰器和事件机制实现功能扩展，支持热插拔。

### 3.6 数据存储系统

数据存储由多个数据库组成：

- AllBotDB: 系统核心数据库
- MessageDB: 消息存储数据库
- KeyvalDB: 键值对存储数据库

系统使用 SQLAlchemy 作为 ORM，支持同步和异步访问。

### 3.7 管理后台

管理后台是一个基于 FastAPI 的 Web 应用，提供：

- 系统状态监控
- 插件管理
- 适配器管理
- Web 对话
- 联系人管理
- 文件管理
- 系统配置
- API 接口

管理后台通过 server.py 启动，支持用户认证和权限控制。

### 3.8 工具库 (utils/)

utils 目录包含系统各种工具和辅助功能：

- 配置管理 (config_manager.py)
- 日志系统 (logger_manager.py)
- 性能监控 (performance_monitor.py)
- 通知服务 (notification_service.py)
- 自动重启 (auto_restart.py)
- 事件管理 (event_manager.py)
- 文件清理 (files_cleanup.py)

## 4. 关键流程

### 4.1 消息处理流程（适配器模式）

1. 适配器接收外部平台消息（QQ/TG/Web/ocwx/wecom_bot 等）
2. 适配器将消息写入 Redis 主队列 `allbot`
3. 消息消费者从 `allbot` 读取消息
4. 核心处理模块处理消息并分发给插件
5. 插件通过 `bot.send_text_message` 等方法发送回复
6. `ReplyRouter` 将回复写入主回复队列 `allbot_reply`
7. `ReplyDispatcher` 按 `platform` 分发到各适配器 `replyQueue`
8. 适配器消费 `replyQueue` 并回写到平台

步骤 3–4 之间，消息在 `utils/allbot/message_router.py` 的 `MessageRouter.process` 中由
`utils/message_normalizer.py` 的 `MessageNormalizer.normalize` **统一归一一次**（幂等），
再按 MsgType 分发；未知 MsgType 一律走 `other_message` 通用出口，绝不丢弃。
归一后字段契约、事件全集与路由表以 [框架消息契约.md](框架消息契约.md) 为唯一事实源。

### 4.2 插件加载流程

1. 系统启动时扫描 plugins 目录
2. 识别符合规范的插件模块
3. 检查插件是否在禁用列表中
4. 加载启用的插件并初始化
5. 注册插件的事件处理器和命令

### 4.3 系统监控和恢复流程

1. 性能监控模块定期收集系统指标
2. 自动重启监控器检查系统状态
3. 当检测到异常状态时触发通知
4. 根据配置决定是否自动重启
5. 记录重启事件和原因

### 4.4 Web 对话流程

1. 用户在管理后台输入消息
2. 前端调用 `POST /api/webchat/send`
3. Web 适配器将消息写入 `allbot`
4. 消息处理流程（同 4.1）
5. Web 适配器从 `allbot_reply:web` 获取回复
6. API 返回回复给前端
7. 前端显示回复消息

## 5. 配置管理

系统配置通过 main_config.toml 文件管理，主要配置项包括：

- ~~协议版本 (Protocol.version) / 框架类型 (Framework.type)~~（历史兼容字段：模板已不含，`config_manager` 仍向后兼容读取并校验，不推荐新配置使用）
- 微信 API 服务器设置 (WechatAPIServer)
- Redis 设置 (redis-host/redis-port)
- ~~WebSocket 设置 (enable-websocket/ws-url)~~（已废弃，WS 由适配器自管）
- RabbitMQ 设置 (enable-rabbitmq)
- 管理后台设置 (Admin)
- 日志系统设置 (Logging)
- 性能监控设置 (Performance)
- AllBot 核心设置 (AllBot)
- 自动重启设置 (AutoRestart)
- 消息过滤设置 (ignore-mode/whitelist/blacklist)
- 系统通知设置 (Notification)

配置通过 utils/config_manager.py 加载和验证，支持热重载。

## 6. 异步设计

系统大量使用 Python 的异步编程模型：

- 使用 asyncio 处理并发操作
- 异步 HTTP 客户端 (aiohttp)
- 异步文件操作 (aiofiles)
- 异步数据库访问 (aiosqlite)
- 异步 WebSocket 通信 (websockets)
- 异步 Redis 客户端 (redis.asyncio)

这种设计使系统能够高效处理大量并发消息和请求。

## 7. 扩展机制

系统提供多种扩展机制：

- **插件系统**：标准插件接口和生命周期管理
- **事件系统**：基于 pub/sub 的事件机制
- **装饰器**：用于注册命令和事件处理器
- **API 接口**：管理后台提供的 RESTful API
- **定时任务**：通过 APScheduler 实现的定时任务系统
- **配置系统**：可扩展的配置管理

## 8. 部署架构

系统支持多种部署方式：

- **直接部署**：在本地机器上运行
- **Docker 容器**：使用 Docker 容器化部署
- **Docker Compose**：使用 docker-compose.yml 编排服务

系统依赖的外部服务：

- Redis 服务器：用于消息队列和缓存
- FFmpeg：用于语音和视频处理

## 9. 安全设计

系统包含多层安全机制：

- 管理后台用户认证
- 管理员权限控制
- 消息黑白名单过滤
- 配置文件权限验证
- 系统状态监控和恢复
- 异常捕获和日志记录

## 10. 总结

AllBot 是一个结构清晰、模块化程度高的微信机器人系统，通过插件系统提供了极高的可扩展性，通过 `adapter/` 支持多平台接入，具备完整的管理功能，是一个功能丰富且稳定的智能机器人解决方案。
