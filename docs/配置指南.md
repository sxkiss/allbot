# AllBot 配置指南

## 1. 配置文件说明

AllBot 使用 TOML 格式配置文件。主配置文件位于项目根目录的 `main_config.toml`，建议基于 `main_config.template.toml` 复制后修改。

插件与适配器各自拥有独立配置文件，位于 `plugins/<name>/config.toml` 与 `adapter/<name>/config.toml`。

## 2. 配置结构总览

`main_config.template.toml` 现含以下 9 个配置段（新配置以此为准，逐键见 §3）：

1. `[WechatAPIServer]` — Redis 连接 / RabbitMQ / 入站消费 worker
2. `[Admin]` — 管理后台
3. `[Logging]` — 日志系统
4. `[Performance]` — 性能监控
5. `[AllBot]` — 版本号、机器人名单、数据库地址、文件清理等核心设置
6. `[AutoRestart]` — 自动重启监控器
7. `[Notification]` — 系统通知
8. `[Notification.triggers]` — 通知触发条件
9. `[Notification.templates]` — 通知模板

> **历史兼容字段（模板已不含，不推荐新配置使用）**：`[Protocol]` 的 `version` 与 `[Framework]` 的 `type`
> 已从 `main_config.template.toml` 移除——主框架完成协议剥离后，协议实现位于 `adapter/<platform>/`，
> 不再由主配置选择协议版本。`utils/config_manager.py` 仍定义 `ProtocolConfig` / `FrameworkConfig`，
> 对旧配置中的这两段**向后兼容读取并做合法性校验**，仅用于旧配置平滑迁移；新建配置无需添加。详见 §3.1、§3.2。

另有一组历史兼容写法：`redis-*` / `enable-rabbitmq` 等的**顶层旧写法**由 `config_manager` 兼容读取（模板现写在
`[WechatAPIServer]` 段内，见 §3.3、§3.4、§3.6）；WebSocket 相关字段（`enable-websocket` / `ws-url` /
`login-qrcode-proxy`）主线已移除，WS 连接由各适配器自行管理。

## 3. 关键配置说明

### 3.1 协议设置（历史兼容字段）

> `main_config.template.toml` **已不含 `[Protocol]` 段**，新配置不推荐使用、也无需添加。
> 主框架已完成协议剥离，协议实现位于 `adapter/<platform>/`（如 `wechat_869`、`wechat_875`），
> 不再通过主配置的 `version` 选择协议版本。
> `utils/config_manager.py` 仍定义 `ProtocolConfig`，对旧配置中的 `[Protocol] version`
> **向后兼容读取并做合法性校验**，仅用于旧配置平滑迁移。

### 3.2 框架设置（历史兼容字段）

> 与 `[Protocol]` 同理：`main_config.template.toml` **已不含 `[Framework]` 段**，新配置不推荐使用。
> `utils/config_manager.py` 仍定义 `FrameworkConfig`，对旧配置中的 `[Framework] type`
> **向后兼容读取并做合法性校验**，仅用于旧配置平滑迁移。

模板真实段清单见 §2 配置结构总览。

### 3.3 WechatAPI 服务配置（`[WechatAPIServer]`）

以下逐键对齐 `main_config.template.toml` 中 `[WechatAPIServer]` 段的真实键：

```toml
[WechatAPIServer]
# Redis 设置
redis-host = "127.0.0.1"
redis-port = 6379
redis-password = ""
redis-db = 0
message-consumer-workers = 8   # allbot 入站并发消费 worker 数（>1 避免慢插件堵全站）

# RabbitMQ 设置
enable-rabbitmq = true
rabbitmq-host = "127.0.0.1"
rabbitmq-port = 5672
rabbitmq-user = "guest"
rabbitmq-password = "guest"
rabbitmq-queue = "example-queue"
```

> 旧版 `host` / `port` / `mode` / `admin-key` 已不在模板中；869 网关 `adminKey` 现配置于
> `adapter/wechat_869/config.toml` 的 `[wechat869]` 段。`message-consumer-workers` 控制入站消费并发，
> 值大于 1 时多 worker 并行处理，避免慢插件堵住全站。

### 3.4 Redis 配置

```toml
redis-host = "127.0.0.1"
redis-port = 6379
redis-password = ""
redis-db = 0
```

Redis 用于消息队列与状态存储，适配器和核心处理流程均依赖该配置。模板把这些键写在 `[WechatAPIServer]` 段内（见 §3.3）；上面这种顶层 `redis-*` 写法属于旧配置，`config_manager` 优先读段内、并向后兼容读取顶层旧写法。

### 3.5 微信协议连接（已迁移到适配器）

> **重要**：主框架已完成「协议剥离」，不再建立任何微信协议连接。
> `enable-websocket` / `ws-url` / `login-qrcode-proxy` / `admin-key` 等旧字段
> 在 `config_manager.py` 中仅为兼容读取，**不产生任何连接行为**。
> 869/875 的网关地址、WS 地址、会话文件、设备码、卡密全部改在
> `adapter/<name>/config.toml` 的 `[wechat869]` / `[wechat875]` 段配置（见 §4）。
> 登录入口统一为：管理后台 → 适配器页面 → 对应适配器「登录」弹窗（扫码）。

旧的顶层写法仅作历史兼容保留，请勿依赖；新配置只写一个地方，避免双开关不一致。

### 3.6 RabbitMQ 设置

```toml
enable-rabbitmq = true
rabbitmq-host = "127.0.0.1"
rabbitmq-port = 5672
rabbitmq-user = "guest"
rabbitmq-password = "guest"
rabbitmq-queue = "example-queue"
```

以上字段仅作历史兼容读取，不再产生连接行为；RabbitMQ 为可选扩展，主链路是 Redis 队列。

### 3.7 管理后台配置

```toml
[Admin]
enabled = true
host = "0.0.0.0"
port = 9090
username = "admin"
password = "change_me"
secret-key = ""  # 可留空，启动自动生成
session-cookie-secure = false
cors-origins = ["http://127.0.0.1", "http://localhost"]
debug = true
log_level = "INFO"
```

- `password` 不能继续使用示例值，至少应替换为强密码。
- `secret-key` 是管理后台会话签名密钥。留空、缺失、仍为模板默认值，或手动填写过短值（<24）时，启动会自动生成至少 24 位随机值并写回 `main_config.toml`。
- `session-cookie-secure` 控制会话 Cookie 是否仅通过 HTTPS 发送；本地 HTTP 调试可为 `false`，正式 HTTPS 部署应改为 `true`。
- `cors-origins` 是允许访问后台的前端来源白名单；开发环境可保留本机地址，生产环境应仅保留实际域名。

### 3.9 核心设置

```toml
[AllBot]
version = "v2.0.0"                # 版本号，请勿修改
ignore-protection = false
enable-group-wakeup = false
group-wakeup-words = ["bot", "机器人"]
robot-names = ["bot"]
robot-wxids = ["wxid_REDACTED"]
github-proxy = ""
AllBotDB-url = "sqlite:///data/allbot.db"
msgDB-url = "sqlite+aiosqlite:///database/message.db"
keyvalDB-url = "sqlite+aiosqlite:///database/keyval.db"

disabled-plugins = []
timezone = "Asia/Shanghai"
auto-restart = false
files-cleanup-days = 1
```

`enable-wechat-login` 已废弃：`main_config.template.toml` 已不含此键，`config_manager` 仅向后兼容读取；主框架不再登录。当前为**统一适配器模式**：所有入站只来自适配器写入的 Redis `allbot` 队列。

## 4. 适配器独立配置

适配器配置文件位于 `adapter/<name>/config.toml`。其中 `ocwx` 表示微信 clawbot 渠道，配置文件路径为 `adapter/ocwx/config.toml`。

### 4.1 ocwx 最小模板

```toml
[adapter]
name = "ocwx"
enabled = false
module = "adapter.ocwx"
class = "OpenClawWeixinAdapter"
replyQueue = "allbot_reply:ocwx"
replyMaxRetry = 3
replyRetryInterval = 2
logEnabled = true
logLevel = "INFO"

[ocwx]
enable = false
platform = "ocwx"

[ocwx.defaults]

[ocwx.redis]

[ocwx.accounts]
```

`[adapter]` 与 `[ocwx]` 是最小必需段；其余三个配置段只用于提示结构，可全部留空。

### 4.2 ocwx 可选配置段

- `[ocwx.defaults]`：覆盖上游接口地址与轮询/超时参数，支持 `baseUrl`、`cdnBaseUrl`、`pollTimeoutMs`、`requestTimeoutMs`、`loginCheckIntervalSec`、`qrRefreshIntervalSec`。
- `[ocwx.redis]`：覆盖专用 Redis 连接，支持 `queue`、`host`、`port`、`db`、`password`。
- `[ocwx.accounts.<slot>]`：声明账号槽位；`<slot>` 可替换成 `main`、`backup` 等任意名称，常用字段为 `enabled`、`displayName`，也可按账号覆盖 `baseUrl`、`cdnBaseUrl`、`pollTimeoutMs` 等。

### 4.3 真实默认值来源

`adapter/ocwx/config.toml` 现在是空模板，不再携带运行示例值。省略配置时，真实默认值来自 `adapter/ocwx/ocwx_adapter.py`：

- `stateDir = "resource/ocwx"`
- `qrDir = "admin/static/temp/ocwx"`
- `replyMediaDir = "admin/static/temp/ocwx/reply-media"`
- `mediaCacheDir = "admin/static/temp/ocwx/media"`
- `baseUrl = "https://ilinkai.weixin.qq.com"`
- `cdnBaseUrl = "https://novac2c.cdn.weixin.qq.com/c2c"`
- `pollTimeoutMs = 35000`
- `requestTimeoutMs = 15000`
- `loginCheckIntervalSec = 3`
- `qrRefreshIntervalSec = 30`
- Redis 优先读取 `main_config.toml` 的 `WechatAPIServer.redis-*`，再回退到 `127.0.0.1:6379/0`

### 4.4 启用 ocwx 前的最低要求

1. 至少新增一个 `[ocwx.accounts.<slot>]` 账号槽位。
2. 把 `[adapter].enabled` 与 `[ocwx].enable` 改为 `true`。
3. 如果默认 Redis 或默认 `openclaw-weixin` 地址不适合当前环境，再补充 `[ocwx.redis]` 或 `[ocwx.defaults]`。

### 4.5 wecom_bot 默认模板

`wecom_bot` 为企业微信智能机器人 **aibot 长连接** 适配器，默认关闭且无凭据：

```toml
[adapter]
name = "wecom_bot"
enabled = false
module = "adapter.wecom_bot"
class = "WecomBotAdapter"
replyQueue = "allbot_reply:wecom_bot"
replyMaxRetry = 3
replyRetryInterval = 2
logEnabled = true
logLevel = "INFO"

[wecom_bot]
enable = false
platform = "wecom_bot"
groupMessagesAsAt = true

[wecom_bot.bots.default]
botId = ""
secret = ""

[wecom_bot.redis]
queue = "allbot"
```

启用前最低要求：

1. 企业微信后台开启智能机器人 **API 模式 → 长连接**，取得 BotID / Secret。
2. 填写 `botId` / `secret`，并把 `enabled` / `enable` 改为 `true`。
3. 主机/容器具备 `ffmpeg`；语音出站使用 `adapter/wecom_bot/bin/amrnb-enc`。
4. 同一 bot 不要并行订阅两条长连接。

详细能力矩阵见 `adapter/wecom_bot/README.md` 与 `docs/multi-platform-adapter.md` §9。

## 5. 使用建议

- 生产环境建议设置强密码，并关闭 `debug`。
- 当前为统一适配器模式，需确保 Redis 可用；`enable-wechat-login` 已废弃。
- 适配器启停为**热插拔即时生效**（无需重启）；主配置/插件配置改动仍建议重启。
- 注意 `adapter/<name>/config.toml` 存在**双开关**：`[adapter].enabled` 与平台段 `enable` 必须一致，否则会出现「起了线程但不干活」的僵尸态。
